# 制导调参顺序

核心原则：**先把"算得对、发得对"核完（开环，不用飞），再调外环增益，最后才碰内环 PID。**
每层一次只改一个数，改完必须回到同一套条件（固定靶、同样发射参数）复现。

## 0. 先分清每层在干什么

| 层 | 在哪里 | 输入 → 输出 | 调参时怎么对待 |
|---|---|---|---|
| 检测 | dart_vision `LabDetector` | 图像 → 导向灯像素框 | 只在丢帧时动（阈值/变焦），与制导效果无关 |
| 解算 | dart_vision `AngleSolver` | 像素 → 视线角 + 角速度 | **不是调出来的，是核出来的**：内参和符号核对一次就定死 |
| 制导律 | dart_vision `control`（`[control]` 段） | 视线角 + `STATE` → **三轴舵角** | **主要调这一层**（pn_gain / aim_error_gain / aim_offset_*） |
| 舵机内环 | simulator `apply_servo_pid` | 期望舵角 → 实际舵角 | 一般不动；怀疑它才用 `enabled = false` 做 A/B |
| 弹道气动 | simulator `[aero]` | 舵角 → 轨迹 | 不动 |

两个容易搞混的认知：

* **仿真器的 PID 不是制导律**。它由 `simulation.rs::apply_servo_pid` 实现，
  做的是 `target_angle = desired + clamp(kp·(desired-current) + …, ±6°)`，
  也就是"让舵面跟上你给的期望角"的**位置环**。给它调参数不会改善制导精度，
  只会改变舵面跟随的动态。
* **仿真器里已经不存在制导律了**。比例导引、视线角速率、灯→靶心换算、交战门限
  全部搬到了 dart_vision 的 `[control]` 段；`guided_dart` 只做四片几何混合、
  舵机模型、气动与刚体。所以不要在 `guided_dart/config/simulator.toml` 里找增益了
  ——那里只剩 `[servo]`、`[servo_pid]`、`[aero]` 和 `[vision]` 的链路/日志参数。
* 闭环需要仿真器回推 `STATE`（位置/速度/姿态）。没有这条回推，视觉端拿不到
  弹道自身的旋转率 γ̇，就只能退化成纯角度导引。

## 1. 第 0 步：核对解算层（开环，不用飞）

仿真器与视觉端的内参必须一致，已核对过的一组：

| 项 | 仿真器 | dart_vision |
|---|---|---|
| 分辨率 | `DAEDALUS_CAPTURE_WIDTH/HEIGHT = 640x480` | `camera.width/height = 640x480` |
| 视场 | `guided_dart/config/simulator.toml [camera] horizontal_fov_deg = 120` | `camera.fov_deg = 120, fov_axis = horizontal` → `fx=fy≈184.75` |

核对符号（10 分钟，不用发射）：

```bash
mkdir -p /tmp/cal && ./build/dart_vision --no-send --no-show \
    --dump-dir /tmp/cal --dump-every 30 --telemetry /tmp/cal/aim.csv
```

* 看 `frame_*.png`：红十字（目标）在中心十字右侧时，`yaw` 必须为正；在中心上方时 `pitch` 必须为正。
* 看 CSV：`center_x > 320` 的行 `yaw_deg > 0`，`center_y < 240` 的行 `pitch_deg > 0`，
  且 `yaw_deg ≈ atan((center_x - 320) / 184.75)`。

常见坑：`fov_axis` 写成 `vertical`（fx 会偏 45%）、改了推流分辨率但没改 `camera`。

## 2. 第 1 步：核对指令链路方向（开环，不用飞）

目的：先排除"指令方向反了/没被识别"这类致命问题，否则后面调增益是白费。

```bash
# 手动发一个 +20° 的 yaw 指令（0.349 rad），观察舵面/模型往哪偏
printf 'GIMBAL 0.349 0\n' | nc 127.0.0.1 7667
printf 'GIMBAL -0.349 0\n' | nc 127.0.0.1 7667
```

* 能确认"报文被识别"的信号：仿真器控制台打印 `外部舵机控制已接管: pitch=.. yaw=.. rad`。
* 若怀疑解析层，用 `tools/fake_dart_command_server.py` 旁路验证（见 README）。
* 判定：`yaw > 0` 舵面向右、`pitch > 0` 舵面向上，且 20° 就是满舵（`[servo] max_angle_deg`）。

## 3. 第 2 步：舵机内环（只有怀疑它才动）

当前参数：`enabled=true, kp=1.5, ki=0.25, kd=0.02, output_limit_deg=6.0`。
真正影响相位的是 `[servo] max_rate_deg_s = 150`——**打满 20° 舵角要 133ms**，
这是一条硬滞后，增益调太大就会被它拖成振荡。

A/B 手法（最有效的判断方式）：

```toml
[servo_pid]
enabled = false     # 直通：target_angle = desired
```

跑同一次发射，对比两次的遥测曲线：

* 关掉后振荡明显变小 → 是内环修正造成的（kp 1.5 在阶跃时最多额外多打 6°），
  可以降 `kp` 到 0.8~1.0、`ki` 到 0.1，或把 `output_limit_deg` 降到 3。
* 关掉后明显变差（跟随慢、末端误差大）→ 保持原值，问题在外环。

判定标准：给一个阶跃舵角指令，舵面 100~200ms 到位、无持续振荡。

## 4. 第 3 步：制导律（外环，主要调这里）

> **注意（2026-09 架构调整后）**：实际在跑的制导律是 `[control]` 段
> （`src/control.cpp`）。下面 4.1~4.3 讲的是旧的 `[guidance]` 段
> ——"视觉只发视线角/角度指令"的链路。仿真器侧的 PN 已经删除，
> 这一段现在**只在离线回放、或者接没有 `STATE` 回推的主控时**才有参考价值。
> 调闭环请直接看 4.6 和 `config/simulator.yaml` 的 `[control]`。

旧链路要切到角度域协议（`szu_uart` 是写实像素框协议，不经过制导律）：

```bash
./build/dart_vision --protocol text_angle --telemetry /tmp/aim.csv   # 旧链路
./build/dart_vision --telemetry /tmp/aim.csv                         # 当前链路（dart_servo）
```

### 4.1 先选对"律"，再谈增益（旧 `guidance` 段）

有两种律，**默认用 `pn`**：

| mode | 消掉的量 | 后果 |
|---|---|---|
| `pn`（比例导引，推荐） | **视线角速度 λ̇** | 与仿真器自带 `[navigation]` 同类，保持碰撞三角、不动弹道形状 |
| `pursuit`（纯追踪） | **视线角误差** | 强迫机头指向目标。飞镖以 35° 仰角起飞、视线角只有约 5.7°，爬升段靶一直在画面下方 30° 左右，于是整个爬升段满舵低头，把弹道压平 → **只能打到基地底部边缘** |

用实测数据看清差别（`record_20260919_161539.mp4` 第一发的爬升段）：

| 时刻 | 视线角误差 | 视线角速度 | pursuit 指令 | pn 指令 |
|---|---|---|---|---|
| t=1.2s | -31.9° | -170°/s | -20°（满舵低头） | -20° |
| t=1.6s | -24.4° | +21°/s | **-20°（继续低头）** | **+15.6°（抬头）** |
| t=2.0s | -12.8° | +30°/s | **-12.8°（低头）** | **+20°（抬头）** |
| t=2.2s | -7.7° | +25°/s | **-7.7°（低头）** | **+18.5°（抬头）** |

符号相反，这就是"接上视觉后突然飞低"的直接原因——不是增益太大，是**把不该归零的量归零了**。

### 4.2 配置与调参

```yaml
guidance:
  enabled: true
  mode: pn                 # 先用 pn；pursuit 只做对照实验
  pn_gain: 4.0             # = 仿真器 navigation.constant (N)
  closing_speed_mps: 18.0  # 接近速度估计（仿真里约 18 m/s）
  lateral_accel_limit: 34.0# = 仿真器 navigation.max_lateral_accel
  k_heading: 0.0           # pn 模式下叠加的"回中"项，默认 0
  max_cmd_deg: 20.0        # 与仿真器 max_angle_deg 一致
  deadband_deg: 0.0
  bias_pitch_deg: 0.0      # 可用来补偿导向灯比靶面低 7cm（见第 5 步）
```

`pn` 模式的指令与仿真器自带 PN 完全等价：
`a_cmd = N·Vc·λ̇` → `fin = clamp(a_cmd / A_max, ±1) × max_cmd`（已逐帧核对，偏差 0.0000°）。
所以**先用 `pn_gain=4.0` 跑一发，它的弹道应该和"不接视觉、纯仿真器 PN"基本重合**——
这是最好的基线自检：如果这一步都打不上导轨，问题在指令链路或符号，不在增益。

调参顺序：

1. 先跑 `mode: pn, pn_gain: 4.0`，确认弹道回到"能上导轨"的水平（与纯 PN 对比）。
2. `pn_gain` 按 2 → 4 → 6 → 8 扫（等效于调 N），看终端误差与过零次数；
   增益过大的表现是末端反向摆、落点散布变大。
3. `closing_speed_mps` 只影响等效增益；远近差异大的场合可以打开单目测距，
   用实测距离替换这个常数（后续可加）。
4. 末端抖动用 `deadband_deg = 0.2~0.5`。
5. 单轴稳了再开 `--axis both`；最后把靶改成 `end_moving` / `random_moving`
   统计命中率（固定 `seed` 与 `launch.json`）。

> 想对照 `pursuit` 律的调法（仅用于理解差异）：`k_heading` 从 1.0 起每次 ×1.5 到
> 刚振荡再退半步，仍有余振加 `k_rate`（0.05→0.1→0.2 s，等效提前 `k_rate/k_heading` 秒）。
> 但注意：这个律**结构上**就不适合弹道飞镖，参数调得再好也只是在跟弹道对着干。

### 4.3 机体系 vs 惯性系：必须补掉弹道自身的低头率

相机是跟着速度矢量转的（`align_to_velocity = true`），所以画面测到的视线角速度是
**机体系**的 θ̇；而比例导引要消的是**惯性系**视线角速度 λ̇。两者差一个弹道自身的
旋转率（近似为重力转弯率）：

```
λ̇ ≈ θ̇ - g/V
```

弹道飞镖在 18 m/s 时 g/V = 0.545 rad/s ≈ **31°/s**，这个量级比视线角速度本身还大，
不补掉就会得到一个"看着合理、方向却反了"的指令。实测（第一发爬升段）：

| 时刻 | θ̇（我测到的） | λ̇ = θ̇ − g/V | 不补偿的指令 | 补偿后的指令 |
|---|---|---|---|---|
| t=1.3s | +10.6°/s | -20.6°/s | +7.8° | -15.3° |
| t=1.6s | +19.5°/s | -11.7°/s | +14.4° | -8.7° |
| t=1.7s | +26.5°/s | -4.7°/s | +19.6° | -3.5° |
| t=1.9s | +30.6°/s | -0.6°/s | **+20.0°（满舵）** | **-0.4°** |
| t=2.1s | +28.2°/s | -3.0°/s | **+20.0°（满舵）** | **-2.2°** |

θ̇ ≈ g/V 说明飞镖其实**已经在碰撞三角上**（机头下落导致的"目标在画面里上飘"
正好被弹道转弯抵消），此时正确指令应该接近 0；不补偿就会一路满舵抬头，
把弹道抬陡、射程缩短——这正是"接入视觉后落点更近"的第二个原因。

```yaml
guidance:
  gravity_turn_comp: true   # 默认开。关掉它相当于退回上面那列"不补偿"的行为
  gravity_mps2: 9.81        # 与仿真器重力一致；改了重力或弹道模型要同步
  closing_speed_mps: 18.0   # 这里的 V 用的是同一个估计值
```

自检方法：`grav_comp: on` 时，**爬升段的 pitch 指令应该是个位数、不饱和**。
如果它依旧长时间停在 ±20°，说明补偿项或 V 估计不对（先用 `--telemetry` 看
`pitch_rate_dps` 是否约等于 31°/s）。

已知近似：`cos γ ≈ 1` 的假设在爬升初期（γ≈35°）会让补偿偏大约 18%；
V 用常数而实际因阻力衰减，越接近目标误差越大。要更准就得引入实测速度和姿态，
或者把导引交回有完整状态的仿真器/主控（见 4.4）。

### 4.4 外部指令现在是"全权接管"，没有内部律可以回落

解耦后 `simulation.rs::guidance` 只做一件事：把外部 `DART` 舵角经四片几何混合
写进舵面期望角。仿真器里不再有 PN、滚转稳定律或竖直偏置项，所以**回落的不是
另一套控制律，而是中立舵**：没有新指令、或超过 `servo_pid.command_timeout_secs`
未收到指令时，舵面归零，镖按纯弹道飞。

| 原来仿真器负责的 | 现在的归属 |
|---|---|
| `roll_command = -roll_error × max_roll_angle`（滚转稳定） | 视觉端的 roll 通道（`DART` 的第三个量）；默认 `[aero] fin_torque_scale = 0` 时四片净力为零、只产生力矩，所以只有开启逐片力矩后 roll 才有物理意义 |
| `+ Vec3::NEG_Y * constant_bias`（常值竖直偏置） | `[control] accel_bias_mps2` |
| 视线角→世界系、λ̇ 差分、低通、跳变抑制 | `src/control.cpp` 的 `DartController` |
| 灯→靶心几何换算、交战门限 | `[control] aim_offset_up_m / aim_offset_forward_m / engage_range_m` |

视觉端要算这些量，必须拿到镖自己的速度和姿态——这就是仿真器回推 `STATE` 的原因。

### 4.5 发射前必须发中立舵（历史最大的坑，两侧都已修）

旧代码里**外部接管分支排在 `if !state.launched` 之前**，所以只要视觉在发指令，
**发射前舵面就已经被外部指令驱动了**。而发射前镖是静止的、
导向灯在画面里几乎不动（视线角速度≈0），比例导引 + 重力补偿会把"0 角速度"
解释成 -g/V ≈ -31°/s，于是给出 **-20° 满舵低头**：

```
发射前：cmd_pitch = -20°（满舵低头）   ← 实测就是这一条
按 F 出膛 → 镖带着满舵低头起飞 → 弹道被压到基地底部
```

视觉侧的修法（旧 `guidance` 段的 `arm_on_motion_deg` + `arm_delay_ms`）：

```yaml
guidance:
  arm_on_motion_deg: 3.0   # 视线角偏离"捕获值"超过 3° 才认为镖在动
  arm_delay_ms: 150.0      # 判定为动之后的稳定期，期间仍不发动作
```

实测（同一段录像）：发射前 `cmd_pitch = 0°`；整段 pitch 指令中位数从 17° 降到 0°，
饱和帧占比从 46% 降到 6%（剩下的 6% 是出膛瞬态的最后约 70ms，可用
`arm_delay_ms: 250` 再压掉）。

**更彻底的修法在仿真器侧（已落地）**：`guidance()` 的第一件事就是
`if !state.launched || state.target_hit { 舵面归零; return; }`，
排在外部指令分支之前。所以现在不管视觉端发什么，发射前与命中后舵面都是零，
这一坑不可能再复现；`[control]` 侧也就不需要 `arm_*` 那套判定。

### 4.6 当前架构：仿真只管物理，控制全部在视觉端

之前试过"视觉只发视线角、仿真器做 PN"（`[vision] aim_as_los = true`）。
那个方案的问题是职责错位：飞镖的真实控制律明明在飞控/视觉端，却让仿真器
替它实现了一遍，于是每次调参都要在"物理参数"和"控制参数"之间来回改仿真器。

现在按解耦原则重做：

```text
图像 → 导向灯中心 (u,v) → 机体系视线角 θ_yaw / θ_pitch
     + STATE（位置 / 速度 / 四元数，50Hz 回推）
  → 机体系 → 世界系（相机姿态与 align_camera_to_flight 一致）
  → 单目测距（导向灯直径 0.20 m）
  → 灯 → 靶心几何换算（aim_offset_up_m / aim_offset_forward_m）
  → 相邻样本差分得 λ̇（跳变抑制 + 低通，按样本时刻而非帧时刻）
  → a = N·Vc·λ̇ + accel_bias_mps2 + 瞄点误差反馈
  → 转回机体系 → 舵角
  → DART <pitch> <yaw> <roll> ─────────────▶ 仿真器（四片混合 + 舵机 + 气动）
```

* 视觉侧：`[control] enabled: true`，`command.protocol: dart_servo`
* 仿真器侧：`guided_dart/src/control.rs` 只解析 `DART`/`SERVO`/`GIMBAL`/`FIRE`
  与遗留的像素帧；`simulation.rs::guidance` 只做四片混合与中立兜底。
  `[navigation]` 段、`AIM` 视线角解析、弹道预测器都已删除。
* 兜底行为：指令超时 / 未发射 / 已命中 → 舵面回中立，镖按纯弹道飞。
  （想验证"关掉视觉制导"的弹道，不发 `DART` 即可。）

这样调参就只剩下一套量，全在 `config/simulator.yaml` 的 `[control]` 段：
`pn_gain`（N）、`accel_bias_mps2`、`aim_error_gain`、`aim_offset_up_m`、
`engage_range_m`、`availability_mps2`、`rate_filter_secs`、`max_sample_jump_deg`。

验收指标（`tools/plot_aim_telemetry.py`）：

| 指标 | 目标 |
|---|---|
| 终端 1s 平均 \|误差\| | < 0.5° |
| 终端 1s 平均视线角速率 | < 1°/s（趋 0 = 在收敛） |
| yaw 过零次数 | ≤ 2 |
| 控制中断（>0.3s 未命中） | 0 段 |

## 5. 第 4 步：系统性瞄点偏差（导向灯比靶面低 7cm）

### 用两轮数据反解常值偏置 `accel_bias_mps2`

`engage_ramp_secs` 和 `accel_bias_mps2` 是一对正交的旋钮，分工必须分清：

* **斜坡管抖动**：门限开启是个阶跃，而门限的开启时刻每发会差 0.2s
  （单目测距在 4~5px 那一档，1 个像素就是 20~25% 的距离），
  阶跃时刻抖动 × 阶跃幅度 = 落点抖动。斜坡把它摊开。
* **偏置管均值**：斜坡同时也削掉了那段阶跃里"有用"的部分，
  于是整体抬高（实测 +0.32m）。用常值偏置把这一档补回来。

偏置到落点是**线性**的，所以两轮数据就能解出来（`b` 的单位是 m/s²）：

```
第 1 点：b = 0     → dy0      （已知，例如 +0.323 m）
第 2 点：b = b1    → dy1      （跑一轮量出来，b1 取 -1.0 通常就够）

灵敏度  k  = (dy1 - dy0) / b1        [m 每 (m/s²)]
最终值  b* = -dy0 / k
```

例：`dy0 = +0.323`、`b1 = -1.0`、量到 `dy1 = +0.15`，
则 `k = 0.173`，`b* = -1.87`。

符号约定（`control.cpp` 里是 `accel += Vec3(0, bias, 0)`，世界系 +Y 向上）：

* **正值 = 向上**，负值 = 向下。
* 落点偏高就往负方向调。（早期注释写反过，注意。）

注意这一步的前提是**散布已经足够小**：如果 `dy@1.0m` 的标准差还在 0.05m 量级，
两轮均值之差会被轮次间漂移淹没，先解决抖动再解偏置。

`[base.guide_light] local_offset = [0.0, -0.07, 0.10]`：导向灯在靶面中心
**下方 7cm**、朝发射方 10cm。视觉只把灯压到光轴中心时，弹着点会**偏低 7cm**，
远距离看不出来、近距离非常明显。

**当前链路（推荐）**：`[control] aim_offset_up_m = 0.14`（灯相对靶心的竖直偏移）
配合 `aim_offset_forward_m = 0.10`，由 `src/control.cpp` 按实测距离做几何换算
（`靶心方向 = normalize(灯方向 × 距离 + 偏移)`），**角度随距离自动变化**，
不需要再手算下面这张表。填 0 = 关闭。

**旧链路**：`guidance.bias_pitch_deg = atan(0.07 / distance) × 180/π` 固定偏置。

| 距离 | 需要的俯仰偏置 |
|---|---|
| 20 m | +0.20° |
| 10 m | +0.40° |
| 5 m | +0.80° |
| 3 m | +1.34° |

要么按单目测距动态算（`solver.light_diameter_m` 打开），要么先用一个固定偏置
（例如 +0.4°）跑通，再决定要不要动态补偿。

## 7. 【2026-09-22 重写】当前制导律 = 含重力的 ZEM；旧 PN+瞄点误差律已弃用

### 7.1 为什么换：旧律里根本没有"位置反馈"

旧律 `a = N·Vc·λ̇ + aim_error_gain·2Vc²/R·(瞄点方向−绿灯方向) + 偏置`
看起来有两项，但第二项吃的是**灯→靶心**的固定几何偏角（终端只有 0.2~0.3°），
不含任何位置信息。于是闭环里唯一的修正来自 PN 的 λ̇ 项，而
`N·Vc·λ̇` 对"静止靶 + 静态偏差"只是一个很软的比例项。

实测（seed 999、15 发、靶沿导轨随机 ±0.37 m）：

| 量 | 数值 |
|---|---|
| 靶位横移跨度 → 镖过靶横移跨度 | 0.749 m → 0.098 m |
| **横向跟踪增益（x_镖 对 target_x 回归斜率）** | **+0.133**（相关 +0.999）|
| 把 `pn_gain` 0.4→1.6 | 跟踪 0.133→0.64，但竖向从 +0.07 掉到 −0.53 m |

斜率为 0.133 而相关 +0.999 说明：方向对、比例只做了 13% —— 这就是
"yaw 制导完全跟不上"的干净量化定义。提高 PN 增益能补横向，但 λ̇ 项会把
**弹道本身因重力产生的低头**当成脱靶去修，竖向立刻过冲。

### 7.2 新律：含重力的零控脱靶量（ZEM），只取垂直于速度的分量

```
T   = R / Vc                      # 剩余飞行时间（单目测距给的 R）
miss = 瞄点 − ( p + v·T + ½gT² )   # 舵面不再出力的自由弹道会落在哪
miss⟂ = miss − v̂·(miss·v̂)          # 只留垂直于速度的那一半
a    = zem_gain · (2 / T²) · miss⟂ # 双积分器最小时间解
```

三个必须同时满足的要点，缺任何一个都会出现"制导把镖压到靶下方 0.5 m"：

1. **必须含 ½gT²**。纯弹道实测只在靶面高 **+0.083 m**（弹道角 −37.9°），
   也就是竖向几乎不用修。按直线外推算 miss，会把重力本来就会给的下坠
   算进偏差里，再补一遍 → 实测 −0.54 m。
2. **必须投影掉沿速度方向的分量**。`T` 是用到**绿灯**的斜距算的，而瞄点在
   灯后面 0.10 m，所以预测点天然"冲过"瞄点平面 ~0.8 m；这一项乘 2/T² 是
   ~8 m/s² 的**倒推力**，映到机体系竖直轴就是 −20° 下压舵。
   物理上舵面产生的力垂直于来流（开环实测纯 +10° 俯仰舵 → 机体力
   `(0,+3.52,−0.90) N`，无轴向分量），所以轴向分量本来就不可控。
3. **瞄点用几何真值**。绿灯在靶面中心**下方 0.07 m、前方 0.10 m**
   （`local_offset = [0,-0.07,0.10]`），所以 `aim_offset_up_m` 的物理值是
   **+0.07**、`aim_offset_forward_m` 是 **+0.10**。旧配置里的负值是历史上
   为对抗饱和而叠的补偿，这一版全部作废。

### 7.3 命中口径：只有仿真器直接测的"机头相对靶心"才算数

镖的碰撞盒是 0.114×0.114×0.2346，靶面只有 0.926×**0.066**×0.085 ——
靶面比镖还薄。所以"hit 位"可以在机头从靶面上方/下方过去时照样触发
（擦靶板下沿）。凡是拿 `hit` 位或"过靶面点"当精度指标，都会被这一点骗到。

`guided_dart/src/base.rs` 现在在命中瞬间直接打印机头几何：

```
命中几何: 机头相对靶心 Δx=+0.0883 Δy=+0.0252 Δz=-0.0429 m (靶面 0.926x0.066) -> 机头命中靶面
```

`Δy` 超出 ±0.0328 就是竖向脱靶（上/下），`Δx` 超出 ±0.463 是横向脱靶。
取这一行做统计，才是"机头是否打在靶面上"的唯一可靠依据。

### 7.4 当前定稿参数与实测结果

`config/simulator.yaml`：

zem_gain: 1.0           # 1.0 = 最小时间解（指令本身按可用加速度限幅，不会发散）

### 7.5 换发射条件后怎么重新校靶（一次收敛）

3. `aim_offset_up_m += −m / 1.0`（ZEM 的瞄点是位置量，灵敏度实测≈1:1）。
   例：m=+0.063 → 0.112−0.063=+0.049。
4. 再跑一轮确认 |Δy| 均值 < 0.01 m、散在 ±0.03 m 内即可收工。

### 7.8 视觉上"打到绿灯上"是怎么回事（2026-09-22 追加）

仿真器里的引导灯是**纯视觉标记**（`GuideLightMarker` 只有 `Mesh3d`/`MeshMaterial3d`，
**没有 `Collider`**），所以它物理上不可能被命中——`hit` 一定来自装甲板碰撞。

但原来的标记半径 0.10 m 是**靶面半高（0.0328 m）的 3 倍**，球心在靶心下方
0.07 m、前方 0.10 m，于是：

```
球顶 y = -0.3856   vs   靶面上沿 y = -0.3828   （只差 2.8 mm）
命中瞬间机头 (y,z)=(-0.4176,-0.8197)，到球心 0.0887 m < r=0.10  →  在球内 1.13 cm
```

也就是说：**只要机头打在靶面上，它就必然落在标记球内部**，从第三视角看就像
"制导把镖打到绿灯上了"。把瞄点抬到靶面上沿（Δy=+0.031）也只能让球面余量
到 +1.6 cm。这是标记尺寸不合理造成的视觉误导，不是制导瞄错了。

处理（2026-09-22 已改）：

* `guided_dart/config/simulator.toml`：`[base.guide_light] radius: 0.10 → 0.05`
  （球顶落在靶心下方 0.02 m，机头打靶心时离球面还余 4 cm）。无碰撞体，纯显示，
  **不影响物理**。
* `dart_vision/config/simulator.yaml`：`light_diameter_m: 0.20 → 0.10`
  （`[control]` 与 `[solver]` 两处）。**必须 = 2×radius**：单目测距是
  `R = D·fx/像素数`，D 与表观像素同比缩放，解出的距离才不变，ZEM 的 `T` 与
  瞄点几何都不需要重调。真机换实际灯尺寸时同样成比例改这两个数。
* 顺手把 `aim_offset_up_m: 0.112 → 0.122`（落点从靶心中线抬到中线偏上，
  给"靶面下沿不算命中"留余量）。

改后实测（灯半径 0.05）：

| seed | 物理命中 | **机头命中靶面** | 竖向 Δy | 横向 Δx | 机头到灯面最小余量 |
|---|---|---|---|---|---|
| 999 | 15/15 | **15/15** | +0.0065 ± 0.0104 m | +0.0012 ± 0.0731 m | +0.006 m（全在球外）|
| 2026 | 15/15 | **15/15** | +0.0075 ± 0.0109 m | +0.0207 ± 0.0876 m | +0.010 m（全在球外）|

检测率从 96.7% 降到 93.7%（灯变小、像素变少），仍远高于可用水平。

### 7.9 镖的碰撞盒不能用"整个包围盒"（2026-09-22 追加，重要）

`[model] collider_size_m` 原来取的是**整个网格包围盒** `0.1144 × 0.1144 × 0.2346`。
这个 0.1144 是**四片尾翼的翼展**，而尾翼是厚 2 mm 的薄片；真实镖体
（`前段镖身`/`后段镖身`/`舵机盒`）横向只有 **4.2 ~ 5.1 cm**。

于是仿真里的镖其实是一根 **11.4 cm 见方的实心梁**在飞，直接导致三个假象：

1. **方块擦到靶板下沿就算命中** —— 所以才会出现"命中的都在装甲板最下方"；
2. **飞到靶面前先撞上旁边的实体** —— 真实镖头根本够不到的东西，方块会先碰到；
3. **第三视角里镖头压在绿色引导灯上** —— 方块把灯的球体"抱"住了。

改成真实镖身尺寸后：

```toml
collider_size_m = [0.05, 0.05, 0.23462799]   # 回退值：0.11440654/0.11441161/0.23462799
```

**"命中"才约等于"镖体真的打到装甲板"**。配合 7.8 节的灯尺寸修正（半径 0.10→0.05）
与 `light_diameter_m: 0.10`，实测（seed 999，15 发/轮）：

| 配置 | 装甲板命中 | 撞到绿灯的次数 | 机头过靶 Δy |
|---|---|---|---|
| 真实镖身 + 灯非实体 | 15/15 | 0 | +0.019 ± 0.022 m |
| 真实镖身 + 灯**实体**（最坏情况） | 15/15 | **0** | +0.009 ± 0.031 m |
| 旧包围盒碰撞盒 + 灯实体 | 15/15 | 3 | +0.008 |

### 7.10 历次实测汇总表（删日志前的归档）

`simulator_system/simulator/hit_geometry_summary.csv` 是历次 15 发轮次的命中几何总表
（64 轮，46 轮有有效几何），列含义：

| 列 | 含义 |
|---|---|
| `tag` | 轮次标签（对应当时的配置/实验） |
| `src` | `sim` = 仿真器直接测的机头几何（权威）；`est` = 用弹道外推估的（旧轮次，仅趋势参考） |
| `shots` / `hit` | 发数 / 仿真器判定的装甲板命中数 |
| `on_plate` | 机头点在靶面矩形内（±0.463 × ±0.0328）的发数 |
| `dx` / `dy` | 机头相对靶心的横向/竖向均值；`dy_sd` = 轮内标准差 |
| `light_contacts` | 该轮镖与**引导灯实体碰撞体**的接触次数（需 `collider = true`） |
| `slope` | 横向跟踪增益（镖过靶横向位置对靶位回归斜率，1 = 完全跟住） |

> ⚠ `est` 那部分有系统性偏差（外推起点不是真实接触时刻），只用于看**趋势**
> （旧配置普遍偏高 +0.09~+0.17 m，现行配置 +0.00~+0.02 m），不要当精度指标引用。

**闭环轮次间漂移（重要限制）**：同一配置连跑，"机头过靶 Δy 的轮均值"会在
`+0.025 / +0.019 / +0.008 / −0.004` 之间跳。原因是**仿真渲染帧率 → 取像帧率 →
视觉输入帧率**这条链：开 `DAEDALUS_RECORD_DIR` 录像时渲染帧率从 ~55 掉到 ~26，
视觉拿到图像的帧率跟着掉，轮均值整体偏约 2 cm。**开录像的轮次不能和不开录像的
轮次直接比数**；要继续压精度，要动的是这一条链（帧率/延迟），不是瞄点。
