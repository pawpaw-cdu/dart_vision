# 控制层 C 移植包（给电控/MCU）

这是 `dart_vision/src/control.cpp`（视觉端跑的那份制导律）的 **C99 逐行对照移植**，
外加从仿真器 `guided_dart` 移植的**四片舵机几何混合**与**舵机位置环**。

| 文件 | 内容 |
|---|---|
| `dv_control.h` | 接口：状态/配置/输出结构体、函数声明、单位与坐标约定 |
| `dv_control.c` | 实现：制导律 + 像素→视线角 + 四片混合 + 舵机位置环 |
| `dv_control_example.c` | 用法示例兼自检程序（伪造一条弹道跑一遍） |

```bash
cc -std=c99 -Wall -Wextra -pedantic -O2 dv_control.c dv_control_example.c -lm -o dv_demo && ./dv_demo
```

特性：**无动态内存、无 IO、无第三方库**，只用 `<math.h>`；`float` 单精度；
所有跨帧状态都在 `dv_control_state` / `dv_servo_state` 里（放全局或静态区）。

---

## 1. 这一层在整条链里的位置

```
[相机] → [检测+解算]  →  机体系视线角 (yaw,pitch) + 灯像素尺寸
                              │
                              ▼
                    ┌──────────────────────┐
[IMU/姿态] ────────►│  dv_control_step     │──► 三轴舵角 (pitch,yaw,roll)
[速度/空速] ───────►│  (本文件)            │         │
                    └──────────────────────┘         ▼
                                            dv_mix_fins  四片舵角
                                                   │
                                                   ▼
                                            dv_servo_step 位置环 + 速率限幅 → 执行器
```

* 视觉端只出**机体系视线角**和灯的像素尺寸（不参与制导计算）。
* 电控负责姿态/速度（IMU + 惯导）与制导律（本文件）。
* **上升段不制导**：靠 `engage_after_launch_secs` 门限卡住（当前 1.40 s），
  比赛里上升段有场地遮挡、也本来就不做视觉制导。

## 2. 调用方式（关键）

```c
dv_config cfg;               dv_config_default(&cfg);   /* 上电一次；再按本机实测覆盖 */
dv_control_state st;         dv_control_init(&st);      /* 上电一次；换发时 dv_control_reset(&st) */
dv_set_warn_hook(my_log);    /* 可选：告警打到串口/日志 */

/* ≥100 Hz 的循环里（与姿态回路同频） */
dv_state s = { ... };        /* 填 IMU/惯导：valid/launched/hit/t_ms/velocity/rotation/available_accel */
/* los_t_ms = 这一对视线角的视觉时刻；控制比视觉快时它保持不变 */
dv_output o = dv_control_step(&st, &cfg, los_yaw, los_pitch, blob_px,
                              los_t_ms, &s, t_ms);
/* o.pitch/yaw/roll 单位弧度；o.active==0 时舵面回中立 */
```

* **可以高频调用**：视觉 30 Hz 时，在两次视觉之间把同一对 `los_yaw/los_pitch` 重复传入、
  只更新 `state` 和 `t_ms`、保持 `los_t_ms` 不变 —— 内部只在 `los_t_ms` 前进时才对
  视线角做差分，所以高频调用不会把视线角速率算成 0（也不受调用频率影响）。
  控制与视觉同频时，直接传 `los_t_ms == t_ms` 即可。
* `t_ms` 用**单调时钟**（与 `state.t_ms` 同一个钟）。视觉帧用「该帧到达电控的时刻」，
  不要用图像的采集时刻，否则会引入额外的传输延迟。
* 若电控直接拿图像坐标，用 `dv_pixel_to_los()` 换算，别自己写（符号很容易错）。

### 2.1 等价性自检（移植后先跑这个）

```bash
./selftest/compare.sh              # 正常路径
AVAIL_ZERO=1 ./selftest/compare.sh # 兜底标定分支
```

它会让 **C++ 原版（`dart_vision/src/control.cpp`）**和 **C 移植版**吃同一串确定性输入
（700 帧、200 Hz 控制 + 30 Hz 视觉、发射后 1.4 s 开门限、斜坡、饱和都覆盖），逐帧对比：

```

  pitch      最大绝对差 2.800e-08 rad 容差 1e-06  OK
  yaw        最大绝对差 8.400e-08 rad 容差 1e-06  OK
  roll       最大绝对差 0.000e+00 rad 容差 1e-06  OK
  los_rate   最大绝对差 7.200e-05     容差 1e-03  OK
  range      最大绝对差 3.000e-07     容差 1e-05  OK
  accel      最大绝对差 5.340e-05     容差 1e-03  OK
  avail      最大绝对差 0.000e+00     容差 1e-05  OK
  aim_err    最大绝对差 4.237e-04     容差 1e-02  OK
  ramp       最大绝对差 2.900e-08     容差 1e-06  OK
  roll_deg   最大绝对差 0.000e+00     容差 1e-06  OK
```

> `aim_err` / `los_rate` 的容差放宽到 1e-3 是正常的：它们经 `acos/acosf` 计算，
> 在角度接近 0 时导数无穷（条件数极差），C++ 用 `double`、C 用 `float`，
> 差 1e-4 属于舍入级。**控制律真正输出的 pitch/yaw/roll 差在 1e-7 rad（=1.6e-6 度）以内。**

## 3. 单位与坐标系（移植第一件事就是核对这个）

### 3.1 约定

| 量 | 约定 |
|---|---|
| 机体系 | **x 右、y 上、机头朝 −z**（仿真/Bevy 约定，视觉端解算也在这套下） |
| 世界系 | 右手系，**y 向上**，重力 = `(0, −g, 0)` |
| `los_yaw_rad` | 机体系视线角，**右正**；`los_pitch_rad` **上正** |
| 距离 | 米；速度 m/s；角速度 度/秒（只在诊断里） |
| 舵角 | **弧度**（`pitch/yaw/roll` 三轴指令，不是四片角度） |
| 四元数 | `(w, x, y, z)`，机体系 → 世界系 |

### 3.2 常见 IMU 约定的换算

如果你们姿态解算输出的是「**x 前、y 右、z 下**」（航空常用）：

```
世界系（x 右, y 上, z 后? 不 —— 本文件世界系是 x 右, y 上, z 朝靶内）
```

本文件的世界系与机体系都是「y 上、机头 −z」，即：

```
机体系: +x 右、+y 上、+z 朝机尾
世界系: +x 右、+y 上、+z 沿发射方向（朝靶）
```

把 IMU 的四元数 `q_imu`（机体系 x前/y右/z下 → 世界系 NED，或者 ENU）转过来时，最稳妥的做法是：
**不要手推矩阵**，而是构造一个「安装矩阵」`C`（3×3），保证下面三条同时成立，然后逐条用静止状态验证：

1. 静止摆放时 `dv_rotate(q, (0,0,-1))` 应指向**弹道方向**（不是机头朝上/朝侧）；
2. `dv_rotate(q, (0,1,0))` 应大致指向**天**（发射仰角 35.5° 时它应比水平高 35.5°）；
3. 发一个 **+10° 的纯 pitch 指令**（既可用 `dv_config.pitch_open_loop_deg = 10` 走开环），
   实物/半实物上应看到**机头抬起**；+10° yaw 应看到**头向右偏**；符号错了就翻对应那一列。

这三条是仿真里验证过同一套约定的方法（开环实测：纯 +10° pitch 舵 → 机体力
`(0, +3.52, −0.90)` N，yaw 舵 → `(+4.24, 0, +1.39)` N），移植后请照做一遍。

### 3.3 视觉给的视线角从哪来

若是像素坐标：`dv_pixel_to_los(u, v, fx, fy, cx, cy, &yaw, &pitch)`，
其中 `yaw=atan((u−cx)/fx)`、`pitch=atan((cy−v)/fy)`（图像 v 向下，故取 `cy−v`）。

## 4. 制导律：结构、参数、为什么这么定

```
T      = R / Vc                                  （剩余飞行时间，R = 单目测距）
aim    = 灯位置 + (0, aim_offset_up, aim_offset_forward) − forward·nose_lead
miss   = aim − ( p + v·T + ½gT² )                 （舵面不再出力的自由弹道会落在哪）
miss⊥  = miss − v̂(miss·v̂)                        （只留垂直于速度的分量）
a      = pn_gain·Vc·λ̇  +  (0, accel_bias, 0)  +  zem_gain·(2/T²)·miss⊥  + 瞄点偏角项
舵角   = clamp(a_机体系 / a_可用, ±1) × max_fin × ramp
```

### 4.1 三个必须同时满足的点（否则会出现"制导把镖压到靶下 0.5 m"）

1. **`½gT²` 不能漏**。纯弹道实测只在靶面高 **+0.083 m**（弹道角 −37.9°），
   竖向几乎不用修。按**直线**外推算 miss 会把重力本来就会给的下坠当成脱靶再补一遍
   → 实测落点低 **−0.54 m**。
2. **必须投影掉沿速度分量**。`T` 用的是到**绿灯**的斜距，而瞄点在灯后面 0.10 m，
   预测点天然"冲过"瞄点平面约 0.8 m；这项乘 `2/T²` 是 ~8 m/s² 的**倒推力**，
   映到机体系竖直轴就是 **−20° 下压舵**。物理上舵面力垂直于来流（开环实测无轴向分量）。
3. **瞄机头而不是瞄质心**（`nose_lead_m`）。制导把质心导向瞄点，而判定/裁判看的是
   **镖头**。不回退时实测命中瞬间机头还在靶面前方 0.15 m、上方 0.11 m ——
   画面里就是"镖身擦靶、机头悬在靶面和绿灯之间"。`nose_lead_m = 0.1173`（=镖身半长）。

### 4.2 参数表（当前定稿值 = `dv_config_default()`）

| 参数 | 定稿值 | 说明 / 为什么 |
|---|---|---|
| `zem_gain` | **0.6** | 主力项。`1.0` 是"最小时间解"（最激进）：实测**同一配置**会因视觉帧率 21~28 fps 抖动而在 **12/15 与 0/15 之间翻面**（失败形态是整体下压 0.19 m）。退到 0.6 后两轮复现为 12/15、10/15，Δy 只差 0.0014 m |
| `pn_gain` | **0** | λ̇ 项会把弹道自身因重力产生的低头当成脱靶去修：N=1.6 时竖向从 +0.07 过冲到 −0.53 m。位置反馈已由 ZEM 提供 |
| `aim_error_gain` | **0** | 旧项算的是"灯→靶心"的固定几何偏角（终端仅 0.2~0.3°），**不含位置信息**。它的缺席正是历史上"yaw 完全跟不上"的根因（实测横向跟踪增益只有 0.133 → 换上 ZEM 后 0.95） |
| `nose_lead_m` | 0.1173 | 见 4.1-3 |
| `gravity_mps2` | 9.81 | 必须与真实一致；和仿真器 `[aero] gravity_scale` 对应 |
| `aim_offset_up_m` | **0.140** | 物理几何 = 灯在靶心下方 **0.07**（`guide_light.local_offset=[0,-0.07,0.10]`）+ 校靶余量。**换发射角/初速/配重后必须重校**（见 §6） |
| `aim_offset_forward_m` | 0.10 | 灯在靶面前方 0.10 m |
| `light_diameter_m` | 0.10 | 必须 = 2×仿真/实物灯的半径；改灯就改这里，单目测距 `R = D·fx/像素` |
| `focal_px` | 301.72 | 640×480、竖直 77° 视场下 `fx=fy=240/tan(38.5°)` |
| `range_min_blob_px` | 4.0 | 灯像素小于它 → 不做灯→靶心换算（2~3 px 时 ±25% 距离抖动会变成几十厘米散布） |
| `rate_filter_secs` | 0.12 | λ̇ 低通（30 fps 时 α≈0.22） |
| `max_sample_jump_deg` | 3.0 | 相邻样本跳变超阈值不更新速率（拦检测跳变/换目标） |
| `engage_after_launch_secs` | **1.40** | 交战门限。用"发射后计时"而不是单目测距，逐发介入点一致（测距口径下逐发开启时刻差 0.16 s、落点漂 0.17 m） |
| `engage_ramp_secs` | 0.25 | 门限打开后指令斜坡，摊平阶跃冲击 |
| `max_fin_deg` | 20.0 | 与舵机机械限幅一致 |
| `roll_gain` | 0 | 主动稳滚，当前关（见 §7 遗留问题） |
| `availability_mps2` / `reference_speed_mps` | 6.7 / 18 | **仅兜底**：拿不到 `state.available_accel` 时才用。⚠ 14 m/s 时兜底值 ≈4.0 m/s²，而真实可用 ≈8.0 → **舵角偏大约 2 倍**，会让俯仰过冲、末端发散 |
| `accel_bias_mps2` | 0.2 | 世界系 +Y 常值偏置，微调落点（直流项，不引入抖动） |

### 4.3 满舵可用侧向加速度（`available_accel`）—— 最容易被忽略的一项

舵角 = 指令加速度 ÷ **满舵可用侧向加速度** × 满舵。

* 仿真里这个值由物理算出并回推（14 m/s 时 ≈ **8.0 m/s²**）。
* 真机上请电控按自家舵效算出来填 `dv_state.available_accel`，例如
  `a_avail ≈ 2 · (½ρv²·A_ctrl·C_L·k_舵效) · gain / m`；**填 0 就会走兜底并偏大 2 倍**。
* 代码里已经加了告警：一旦用了兜底，`dv_output.used_fallback_scale = 1` 且
  `dv_warn_hook` 会被调用一次（每 1.5 s 限频）。

## 5. 舵机侧（本文件已含，可直接用）

### 5.1 四片几何混合 `dv_mix_fins`

```
θ_i = gain · ( pitch·cosφ_i − yaw·sinφ_i + roll )
```

`φ_i` = 该片铰链在机体系 x-y 平面内的方位角。本机模型实测（启动日志原值）：

| 片 | 铰链方向 | φ | pitch 系数 | yaw 系数 | roll 系数 |
|---|---|---|---|---|---|
| 尾翼B-1 | (0.71, −0.71, 0) | −45° | +0.71 | +0.71 | +1 |
| 主翼B-1 | (0.71, −0.71, 0) | −45° | +0.71 | +0.71 | +1 |
| 主翼A-1 | (0.71, +0.71, 0) | +45° | +0.71 | −0.71 | +1 |
| 尾翼A-1 | (−0.71, −0.71, 0) | −135° | −0.71 | +0.71 | +1 |

* 性质：纯俯仰/偏航指令 **Σθ=0**（不产生滚转力矩）；滚转指令不产生净侧向力。
* `gain`（几何混合增益）= 0.5 时，制导的满指令只用舵面一半行程；
  `1.0` 时满行程，可用侧向力约翻倍 —— 但**回路增益也会跟着翻倍**，必须和
  `zem_gain` 一起调（仿真里就是"权限 × 控制器增益 = 回路增益"）。
* 若实机是"每轴一片"而不是 X 字四片，直接改 `φ_i` 或改 `dv_mix_fins` 的系数表。

### 5.2 舵机位置环 `dv_servo_step` + 速率限幅 `dv_servo_rate_limit`

来自仿真器 `apply_servo_pid` / `drive_servos`：

```
误差 = 期望角 − 当前角
积分 = clamp(积分 + 误差·dt, ±integral_limit)      （饱和同向时停积分，抗饱和）
修正 = clamp(kp·误差 + ki·积分 + kd·(误差−上拍误差)/dt, ±output_limit)
目标 = clamp(期望角 + 修正, ±max_angle)
实际 = 速率限幅(当前角 → 目标, max_rate·dt)
```

仿真器里的定稿值：`kp=1.0, ki=0.25, kd=0.02, integral_limit=0.35,
output_limit_deg=2.6, max_angle_deg=20, max_rate_deg_s=150`。
这一层只是"让舵面跟上期望角"的**位置环**，它调不好会直接影响制导精度，
但**它不是制导律**（调它不会改变落点，只会改变跟随动态）。

## 6. 换发射条件后怎么重新校靶（一次收敛）

`aim_offset_up_m = 0.140` 里的"余量"部分只对**当前弹道**（仰角 35.5°、
初速 17.661 m/s、当前配重）有效。换条件后：

1. 跑一轮 15 发，用仿真器日志里的机头几何量取 Δy 均值 `m`：
   `grep -A1 命中几何 /tmp/sim_run.log`（`机头相对靶心 Δx=.. Δy=.. Δz=..`）。
2. `aim_offset_up_m += −m`（ZEM 的瞄点是**位置量**，灵敏度实测 ≈1:1）。
3. 再跑一轮确认 |Δy| 均值 < 0.01 m、散布在 ±0.03 m 内。

判读标准（当前配置应有的样子）：

* `Δy` 在 **±0.033** 内（实测 +0.017 ± 0.025）；
* `Δz` 在 **−0.055 ~ −0.043**（−0.0426 是靶面前表面，再加机头小球半径）；
* 碰撞日志里只应出现"装甲板顶部碰撞盒"。

## 8. 已知遗留 / 上限

1. **散布 ±2.5 cm 的主因是视觉帧率**（22~28 fps + 传输/处理延迟）。
   开录像时仿真渲染帧率从 ~55 掉到 ~26，落点均值就偏 ~2 cm ——
   **要继续压精度，动的是这条链（帧率/延迟），不是瞄点。**
2. 横向跟踪增益 ≈0.95（靶 ±0.37 m 横移），横向散布 ±0.08 m；靶面宽 0.926 m，够用。
3. 终端段仍有 20~60° 滚转跨度（`roll_gain=0`、仿真侧 `fin_torque_scale=0`，滚转通道
   没有物理权限）。当前精度不受它影响，但要继续压散布，这是最值得补的一环。
4. 本文件里 `aim_offset_up_m` 的"校靶余量"是**对某一条弹道拟出来的**，
   不是普适常数 —— 每次换弹/换药/换发射角都要按 §6 重校。
